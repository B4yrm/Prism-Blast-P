Date: 2026-11-14. Branch `claude/clever-maxwell-tolun5`, starting from `87831c6`. Plan: `docs/ROADMAP-28-DAYS.md` T1.1.
Approved: Q1 (adapter layer), Q2 (`src/main-eco.js` + `ECO=1`). Q3 is conditional and is not used here: T1.1 writes
nothing to the save.

## 1. What changed

| File | Change |
|---|---|
| `src/eco/rng.js` (new) | Seeded sfc32 streams, one per domain (`catch, weather, market, contracts, events, damage`). Each state is 4 × uint32, JSON-safe. No use of the global random generator. |
| `src/eco/clock.js` (new) | Eco game clock on simulation dt (1 game hour = 60 s); hour, day, season, year helpers. Has an epsilon for float steps (§4, problem 1). |
| `src/eco/adapter.js` (new) | The only place that touches the game. It installs once and checks the contract first. It wraps 7 `stat` functions (`rawPrice, prodPrice, custEvery, boatSpeed, fishTime, boatCap, workerSpeed`) and `Sim.prototype.update`. With eco off, every wrapper returns the original value untouched. With eco on, T1.1 only advances the clock (no modifiers exist yet). |
| `src/eco/index.js` (new) | Calls `install` and exposes the read-only `window.__eco` for tests. `setOn`/`reinstall` are dev/test helpers. Eco is off by default. |
| `src/main-eco.js` (new) | `import './eco/index.js'; import './main.js';` |
| `build.mjs` | `ECO=1` selects `src/main-eco.js`. `ECO=1` without `BUILD_OUT` stops with an error, so the production `index.html` can never be built with eco. Without `ECO` the build is unchanged. |
| `tests/eco/*` (new) | `_load.cjs` (esbuild helper), `rng.test.cjs`, `clock.test.cjs`, `no-math-random.cjs`, `adapter-contract.cjs`, `eco-browser.cjs`, `micro-overhead.cjs`. |

**Unchanged** (checked with `git status` / `git diff`): `src/sim/*`, `src/core/*`, `src/main.js`, `src/scenes/*`, `src/render/*`
(boat routes, berths, jetties, workers phase A), `src/ui/*`, `src/config.js`, `src/data/*`, `fishing/`, `idle/`, `tycoon/index.html`,
`apk/`, `.github/workflows/*`. No production build and no APK were made.

## 4. Problems found

1. **Float drift in the clock (found and fixed in T1.1 code).** 1,800 steps of 1/30 s add up to slightly less than 60 s,
   so 600 s at 30 FPS gave 9 game hours instead of 10. The number of hours would have depended on the frame rate. Fixed
   with an epsilon of 10⁻⁶ s in `clock.js`. Tests 2 and 4 cover it.
2. **Wrong sfc32 reference in my first test (test bug, not a code bug).** Some JS ports of sfc32 add the counter after
   the increment. The original C (PractRand) adds it before, and `rng.js` does the same. The test now uses a port of the C code.
3. **The tests overwrite committed result files.** `workers-regress`, `save-compare`, `boat-sync` and `outer-save` write
   into `test-results/workers/`, `test-results/boat-sync.json` and `test-results/outer-save.json`. The T1.1 results were
   copied to `test-results/eco/t1.1/` and the committed files were restored with `git checkout`, so the phase A results
   in the repo are unchanged. Later tasks need the same care, or an output-path option in those scripts (a test-tool
   change, needs a decision).
4. **Benchmark noise is larger than the effect being measured** (perf-M0 §2). FPS comparisons need several interleaved runs.
   The microbenchmark measures eco's own cost directly.
5. **`boat-timeline.cjs` is not deterministic** (test 12). Keep it for leg durations, and use the seeded tests for identity.
6. **No Android measurement possible** without a workflow change or a production build (Q10).

node tests/eco/no-math-random.cjs
node tests/eco/adapter-contract.cjs
